Create scripts/db-fresh.ts as a TypeScript script run via `npx tsx`.

The script has three phases: reset, migrate, verify.

**Part A: Setup and constants**

```typescript
import { execSync } from 'child_process';
import { readdirSync, readFileSync } from 'fs';
import { join } from 'path';

const GREEN = '\x1b[32m';
const RED = '\x1b[31m';
const YELLOW = '\x1b[33m';
const BOLD = '\x1b[1m';
const RESET = '\x1b[0m';
```

**Part B: Reset + Migrate (subprocess calls)**

- Print header: `\n  ${BOLD}Fresh local database${RESET}\n`
- Step 1 "Reset": Run `npx tsx scripts/db-reset.ts` via execSync with `stdio: 'inherit'` — output streams through
- Step 2 "Migrate": Run `npx tsx scripts/db-migrate.ts` via execSync with `stdio: 'inherit'`
- Both calls throw automatically on non-zero exit (fail-fast from child scripts)

**Part C: Schema verification**

This is the core of this plan. After reset + migrate, verify the schema matches expectations.

1. **Parse migration SQL files to build expected schema:**

Create a `parseMigrations()` function that:
- Reads all .sql files from migrations/ directory, sorted alphabetically (which gives correct order: 0001, 0002, ... 0015)
- Maintains a `Map<string, Array<{name: string, type: string}>>` of table -> columns
- For each file, processes the SQL text to extract:
  - **CREATE TABLE IF NOT EXISTS tableName (...)**: Extract table name and column definitions from the parenthesized block
  - **ALTER TABLE tableName ADD COLUMN colName colType ...**: Add column to existing table entry
  - **DROP TABLE tableName** or **DROP TABLE IF EXISTS tableName**: Remove table from map
  - **ALTER TABLE oldName RENAME TO newName**: Move map entry from oldName to newName

Column parsing within CREATE TABLE:
- Split the parenthesized content by commas that are NOT inside nested parentheses
- For each line, trim whitespace. Skip lines that start with constraint keywords: `PRIMARY KEY(`, `UNIQUE(`, `CHECK(`, `FOREIGN KEY(`, `CREATE INDEX`, or are empty
- Extract column name (first word) and type (second word). If type is omitted, use "" (empty).
- Handle that some columns have types like `TEXT NOT NULL` — just take the first type word (TEXT)
- Handle `INTEGER PRIMARY KEY AUTOINCREMENT` — the type is `INTEGER`

**Critical: migration 0014 handling:**
- 0014 creates `audit_logs_new` (CREATE TABLE IF NOT EXISTS audit_logs_new ...)
- 0014 has `DROP TABLE audit_logs` — remove audit_logs from map
- 0014 has `ALTER TABLE audit_logs_new RENAME TO audit_logs` — rename entry
- Result: audit_logs has the 0014 column set (which is the same columns but with expanded CHECK constraint — columns themselves are identical)

2. **Query actual schema from live database:**

Create a `getActualSchema()` function that:
- Queries `SELECT name FROM sqlite_master WHERE type='table' ORDER BY name` to get all tables
- Filters out `sqlite_sequence`, `_cf_METADATA`, and `d1_migrations` (d1_migrations is wrangler's internal table, not from our migrations)
- For each table, queries `PRAGMA table_info(tableName)` via wrangler CLI
- Returns `Map<string, Array<{name: string, type: string}>>` matching the expected schema format

Use the same wranglerQuery helper as db-reset.ts:
```typescript
function wranglerQuery(sql: string): any[] {
  const result = execSync(
    `npx wrangler d1 execute ratemyplace-db --local --command "${sql.replace(/"/g, '\\"')}" --json`,
    { encoding: 'utf8', stdio: ['pipe', 'pipe', 'pipe'] }
  );
  return JSON.parse(result)[0].results;
}
```

3. **Compare expected vs actual:**

Create a `verifySchema()` function that:
- Calls parseMigrations() and getActualSchema()
- Checks for missing tables (in expected but not in actual)
- Checks for extra tables (in actual but not in expected)
- For each matching table, compares column names and types
  - Missing columns, extra columns, type mismatches
- Collects all differences into an array of error strings
- If no differences: print `  ${GREEN}✓ Schema verified${RESET}` and return true
- If differences found: print each difference with context, print summary, and return false

**Part D: Final output**

- Call verifySchema()
- If verification passes: print `\n  ${GREEN}✓ Database ready${RESET}\n` and exit 0
- If verification fails: print `\n  ${RED}✗ Schema verification failed${RESET}\n` and exit 1

**Key requirements:**
- Schema parsing uses regex — NOT a full SQL parser (research confirms this is sufficient for the predictable migration format)
- Column type comparison should be case-insensitive (SQLite is case-insensitive for types)
- The script must handle running twice in a row (idempotent): first run does reset+migrate+verify; second run does the same thing and succeeds
- d1_migrations table is excluded from verification (it is created by wrangler internally, not by our migration files)
- All errors report which table and column caused the mismatch
