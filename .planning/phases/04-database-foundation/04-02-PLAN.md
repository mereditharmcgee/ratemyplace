3. **Main migration logic:**
- Print header: `\n  Migrate local database\n`
- Step "Counting migrations": Read the migrations/ directory, count .sql files, display count (e.g., "15 migration files found")
- Step "Applying migrations": Execute `npx wrangler d1 migrations apply ratemyplace-db --local` with `stdio: 'inherit'` to show live wrangler output

4. **Error handling:**
- Wrap the execSync call in a try/catch
- On error: print the step that failed, the error message, and stderr if available
- Exit with code 1 on any failure
- The wrangler command outputs its own progress (migration names, success/skip messages) — let that stream through via `stdio: 'inherit'`

Key requirements:
- Use `stdio: 'inherit'` for the wrangler migrations apply command so the user sees live output
- The database name `ratemyplace-db` must match wrangler.jsonc
- Do NOT use `--remote` anywhere — local only
- The `--local` flag ensures no confirmation prompt is shown
- If wrangler reports "No migrations to apply!" that is a success case (exit 0)
- Handle the edge case where wrangler might prompt for confirmation on pending migrations: if it does hang, the research suggests using `--yes` flag or piping stdin.
