**`test.describe('XSS Prevention (SEC-08)')`:**

Test 1: Script tag in dispute explanation renders as escaped text
- Submit dispute via `POST /api/disputes` with:
  - `reviewUrl`: `http://localhost:8788/building/building-01/review/review-060`
  - `disputeExplanation`: `<script>alert('XSS')</script>`
- Navigate to admin disputes page as admin (`adminPage.goto('/admin/disputes')`)
- Verify the text `<script>` appears literally (visible as text, not executed)
- Use `adminPage.locator` to find the escaped text content

Test 2: Image onerror XSS payload renders as escaped text
- Use `review-070` as review target
- `disputeExplanation`: `<img src=x onerror="alert('XSS')">`
- Navigate to admin disputes page, verify literal `<img` text appears as text content

For both SEC-07 and SEC-08 tests, use `adminPage` fixture to navigate admin pages (admin session needed to view disputes). Use bare `request` fixture for the dispute POST submission (disputes are public, no auth needed).

IMPORTANT: Each dispute must target a different review_id due to UNIQUE constraint. Use review-030, review-040, review-060, review-070 (none of these have existing seeded disputes).
