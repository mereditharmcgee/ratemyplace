Schema requirements from research:
```sql
CREATE TABLE IF NOT EXISTS verification_tokens (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    token TEXT UNIQUE NOT NULL,
    created_at INTEGER NOT NULL DEFAULT (unixepoch()),
    expires_at INTEGER NOT NULL
);

CREATE INDEX idx_verification_tokens_user ON verification_tokens(user_id);
CREATE INDEX idx_verification_tokens_token ON verification_tokens(token);
CREATE INDEX idx_verification_tokens_expires ON verification_tokens(expires_at);
```

Key design decisions:
- Use TEXT for id (consistent with users table)
- ON DELETE CASCADE so tokens are removed when user is deleted
- UNIQUE constraint on token for fast lookups
- expires_at as INTEGER (Unix timestamp, consistent with sessions table)
- Index on token for verification lookups
- Index on expires_at for cleanup queries

Create src/lib/tokens.ts with the following exports:

1. `generateVerificationToken(): string`
   - Use @oslojs/crypto generateRandomString with crypto global
   - 64-character alphanumeric token (per research recommendation)
   - Alphabet: A-Za-z0-9

2. `generateTokenExpiry(): number`
   - Returns Unix timestamp 24 hours from now
   - Use Math.floor(Date.now() / 1000) + (24 * 60 * 60)

3. `createVerificationToken(db: D1Database, userId: string): Promise<string>`
   - Generate token using generateVerificationToken()
   - Generate ID using generateIdFromEntropySize(10) from lucia
   - Calculate expiry using generateTokenExpiry()
   - Delete any existing tokens for this user (one active token per user)
   - Insert into verification_tokens table
   - Return the token string (not the id)

4. `validateVerificationToken(db: D1Database, token: string): Promise<{valid: boolean, userId?: string, reason?: string}>`
   - Query verification_tokens for matching token
   - If not found: return {valid: false, reason: 'invalid_token'}
   - If expired (expires_at < now): return {valid: false, reason: 'expired'}
   - If valid: return {valid: true, userId: record.user_id}
   - Do NOT delete token here (caller handles that after marking email verified)

5. `deleteVerificationToken(db: D1Database, token: string): Promise<void>`
   - Delete the token from database
   - Called after successful email verification
