**Helper function: `rateAllItemsInStep(page, score)`**

Create a reusable helper that clicks a specific score button for every rating item visible in the current step:

```typescript
async function rateAllItemsInStep(page: Page, score: number) {
  // Rating items are in div.py-4 containers. Each has buttons 1-5.
  // Click the button matching the score for each item.
  const items = page.locator('.py-4.border-b, .py-4.last\\:border-0').filter({ has: page.locator('button[type="button"]') });
  // Alternative simpler approach: find all buttons with the exact score text
  // that are currently visible in the step
  const scoreButtons = page.locator('button[type="button"]').filter({ hasText: new RegExp(`^${score}$`) });
  const count = await scoreButtons.count();
  for (let i = 0; i < count; i++) {
    await scoreButtons.nth(i).click();
  }
}
```

NOTE: This helper approach may need adjustment. The key insight is that each rating step renders its items with buttons 1-5, and only the current step's buttons are in the DOM (React conditionally renders steps). So clicking ALL visible buttons with text matching the score will rate every item.

ALTERNATIVE approach if the above doesn't work: Find each RatingItem container by its dimension text and click the score button within it. This is more precise but more verbose.

**IMPORTANT implementation notes:**

1. **React hydration timing:** After `goto('/review/new?building=building-30')`, React needs to hydrate. Use `waitForLoadState('networkidle')` or explicitly wait for a visible React element before interacting.

2. **Rating button selection:** The most reliable approach is `page.locator('button[type="button"]').filter({ hasText: /^4$/ })` — this matches buttons whose text is exactly "4". Since only the current step's items are rendered (React conditional rendering), all matched buttons belong to the current step.

3. **Step transition timing:** After clicking Continue/Back, wait for the new step content to appear before interacting. The step transition is synchronous React state change, so it should be near-instant, but a brief `waitFor` on the next step's header text is safer.

4. **The happy-path test is long.** Playwright's default 30-second timeout may be tight for 27 button clicks + navigation + submission. If timeout is a concern, increase the test timeout: `test.setTimeout(60000);`

5. **Building-30 has 0 reviews in seed data.** This means the happy-path test's submitted review will be the first. After the test, the building page should show it (if approved — check if reviews go through moderation).

6. **The Continue button on the last rating step (landlord-rating) navigates to 'additional', not 'confirm'.** The AdditionalStep has a "Review & Submit" button that goes to confirm.
