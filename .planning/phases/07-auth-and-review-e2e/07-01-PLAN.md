Create a new file `e2e/auth.spec.ts` with the following test structure. This file covers E2E-01 (signup), E2E-02 (signin/signout), and E2E-05 (password reset), plus auth error states.

The file must:

1. **Import from './fixtures'** (not '@playwright/test') — matching the project convention
2. **Use ESM __dirname** via `fileURLToPath(import.meta.url)` if path resolution is needed (for wrangler CLI cwd)
3. **Import `execSync` from 'child_process'** for reading D1 tokens via wrangler CLI

The test cases to implement:

**describe('Signup', () => { ... })**

- **'user can sign up with email and password'** (E2E-01):
  - Generate unique email: `signup-${Date.now()}@test.local`
  - Navigate to `/auth/signup`
  - Fill `input[name="email"]` with the unique email
  - Fill `input[name="password"]` with `TestPassword123!`
  - Fill `input[name="confirmPassword"]` with `TestPassword123!`
  - Click `button[type="submit"]`
  - `await page.waitForURL('/')`
  - Assert `form[action="/api/auth/signout"]` is visible (confirms signed-in state)

- **'duplicate email shows error'**:
  - Navigate to `/auth/signup`
  - Fill email with `user@test.ratemyplace.local` (seed user — already exists)
  - Fill password and confirmPassword with `TestPassword123!`
  - Click submit
  - Assert `#error-message` becomes visible (do NOT use `waitForURL('/')` — it should NOT redirect)
  - Assert the error message text contains relevant error content

**describe('Signin and Signout', () => { ... })**

- **'user can sign in with valid credentials'** (E2E-02):
  - Navigate to `/auth/signin`
  - Fill email: `user@test.ratemyplace.local`
  - Fill password: `TestPassword123!`
  - Click submit
  - `await page.waitForURL('/')`
  - Assert signout form is visible

- **'user can sign out'** (E2E-02):
  - Use the `authedPage` fixture (already signed in)
  - Navigate to `/`
  - Click `form[action="/api/auth/signout"] button[type="submit"]` using `.first()` (desktop nav)
  - `await authedPage.waitForURL('/')`
  - Assert `header a[href="/auth/signin"]` is visible (session cleared)
  - Assert signout form is NOT visible

- **'wrong password shows error'**:
  - Navigate to `/auth/signin`
  - Fill email: `user@test.ratemyplace.local`
  - Fill password: `WrongPassword999!`
  - Click submit
  - Assert `#error-message` becomes visible
  - Page should still be on `/auth/signin`

**describe('Password Reset', () => { ... })**

- **'user can request password reset'** (E2E-05 partial):
  - Navigate to `/auth/forgot-password`
  - Fill email: `user@test.ratemyplace.local`
  - Click submit
  - Assert `#success-message` becomes visible
  - Assert success message text indicates email was sent

- **'user can complete full password reset flow'** (E2E-05 full round-trip):
  - Step 1: Request reset
    - Navigate to `/auth/forgot-password`
    - Fill email with a seed user email (use `user@test.ratemyplace.local` or another seed user — NOTE: since we might change this user's password, consider using a different seed user if available, or use user@test.ratemyplace.local and reset back)
    - Click submit
    - Wait for `#success-message` to be visible
  - Step 2: Read token from D1
    - Use `execSync` to run: `npx wrangler d1 execute ratemyplace-db --local --command "SELECT pr.token FROM password_reset_tokens pr JOIN users u ON pr.user_id = u.id WHERE u.email = 'EMAIL' ORDER BY pr.expires_at DESC LIMIT 1"`
    - Parse the wrangler output. Wrangler outputs JSON to stdout. Use a robust parser: try `JSON.parse(raw)`, then look for the token in `parsed[0]?.results?.[0]?.token` or fall back to regex extraction from the raw output.
    - CRITICAL: The table name is `password_reset_tokens`, not `password_resets`.
  - Step 3: Reset password
    - Navigate to `/auth/reset-password?token=${token}`
    - Fill `input[name="password"]` with `NewTestPassword456!`
    - Fill `input[name="confirmPassword"]` with `NewTestPassword456!`
    - Click submit
    - Assert `#success-container` becomes visible
    - Assert text "Password Reset Successfully" is visible
  - Step 4: Sign in with new password
    - Navigate to `/auth/signin`
    - Fill email with the same user email
    - Fill password with `NewTestPassword456!`
    - Click submit
    - `await page.waitForURL('/')`
    - Assert signout form is visible (confirms new password works)
  - Step 5 (cleanup): Reset the password back to the original
    - Since this test modifies a seed user's password, and other tests may depend on the original password, either:
      (a) Use a freshly signed-up user for this test instead, OR
      (b) Reset the password back at the end of the test
    - RECOMMENDED: Use a freshly signed-up user. Sign up with a new email at the start of this test, then do the password reset flow on that new user. This avoids breaking seed user credentials.

- **'invalid reset token shows error'**:
  - Navigate to `/auth/reset-password?token=invalid-token-12345`
  - Fill `input[name="password"]` with `TestPassword123!`
  - Fill `input[name="confirmPassword"]` with `TestPassword123!`
  - Click submit
  - Assert `#error-message` becomes visible
  - Assert `#success-container` is NOT visible

**IMPORTANT implementation notes:**

1. The password reset full round-trip test is the most complex. The wrangler CLI output parsing may need adjustment based on actual output format. Add a try-catch around the parsing with a descriptive error message that includes the raw output for debugging.

2. For the wrangler CLI `cwd`, use `path.resolve(__dirname, '..')` to point to the project root (since auth.spec.ts is in e2e/).

3. All passwords must be at least 8 characters (reset-password.ts enforces 8-char minimum).

4. The `execSync` call for wrangler may take a few seconds. Set a reasonable timeout or use `{ timeout: 30000 }` in the execSync options.

5. For the duplicate email signup test, the API returns `{ error: "Email already registered" }` or similar — assert the #error-message div text rather than a specific message string.

6. The forgot-password API always returns 200 (even for non-existent emails) to prevent user enumeration. So the success message appears regardless of whether the email exists.
