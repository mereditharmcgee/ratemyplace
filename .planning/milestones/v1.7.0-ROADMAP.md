# Roadmap: v1.7.0 "Public Record"

**Created:** 2026-09-07
**Status:** IN PROGRESS. Phase 31 implemented on `feat/building-records`, pending merge
**Milestone goal:** Give every Boston building page a second layer made of primary public records, shown as recorded, cited and dated, so a page is useful to a renter before it has a single review.

**Design:** [`docs/superpowers/specs/2026-09-06-building-records-design.md`](../../docs/superpowers/specs/2026-09-06-building-records-design.md)
**Plan:** [`docs/superpowers/plans/2026-09-06-building-records.md`](../../docs/superpowers/plans/2026-09-06-building-records.md)

## The load-bearing rule

**Reviews are the judgment layer. The records panel has no opinion.** Every rendered value
is a field from a primary record or a count of such records. No ratios, no comparisons, no
grades, no color coding, no inference. Records are not part of any score. Every phase below
inherits this rule, and a phase that cannot hold it does not ship.

## Sequencing principle

The sub-projects ship **A, C, B, D**, which is not their dependency order but their
value order. A is the foundation and applies only to buildings already in the database. C
changes the reader funnel immediately and produces the attention that justifies B's scraper
fragility. B depends on C for that attention, not for code. D is designed last, once a
correction has actually been processed, so the peer group and the indicator are designed
together on the saved-query mechanism rather than bolted on.

## Phase details

### Phase 31: Records foundation (sub-project A)

**Status:** Implemented on `feat/building-records`, pending merge and production migration.

Parcel id and SAM id on `buildings`, the provenance tables (`record_pulls`,
`building_records`, `record_corrections`), the Boston adapters (assessor across six fiscal
years, approved building permits, ISD violations, Public Works code enforcement, 311 across
sixteen legacy yearly resources plus the new system, RentSmart), the admin-triggered pull,
the server-rendered public records panel, and the public correction path with its admin
queue.

**Production actions still outstanding:** migrations `0029` and `0030` applied by hand per
[`migrations/AGENTS.md`](../../migrations/AGENTS.md), then the Lanark pull compared against
the brief by eye and with `npm run records:check`, then the remaining Boston buildings.

### Phase 33: Entity record (sub-project B)

**Status:** Not started. Needs its own spec before implementation.

CorpWeb entity records with retries and a **needs manual verification** flag, an admin
verification UI, manager and resident agent names on the building page, and "other buildings
with the same tax mailing address" on the landlord page. That list is never labelled a
portfolio: a shared mailing address can be a management company or a lawyer's office.
Entity records are new `building_records` kinds; the schema does not change.

### Phase 34: Neighborhood indicator (sub-project D)

**Status:** Not started. Needs its own spec, and does not begin until at least one record
correction has been processed end to end.

A saved-query table for peer groups expressed so a reader can see how the group was chosen,
the zero-permit peer count, and one derived indicator stated as a fact, with the peer
definition published on `/methodology`.

## Relationship to v1.6.0

Two v1.6 phases get materially stronger now that **Phase 32** has landed:

- **Phase 29, Discoverability baseline.** Its public-only sitemap is built here — C3 ships
  `/sitemap.xml`, the chunked `/sitemaps/*.xml` files and `/robots.txt` as D1-backed routes
  — and it is worth far more against a page for every whole-building residential parcel than
  against 91 buildings.
- **Phase 30, Review-density pilot.** A pilot cohort sent to an address that already shows
  the city's records on that building converts differently from one sent to an empty page.

The v1.6 roadmap line deferring "neighborhood content farms" and the reader-acquisition
deferral in [`ops/growth/STRATEGY.md`](../../ops/growth/STRATEGY.md) were both written
before records existed. The strategy decision log dated 2026-09-06 recorded the inversion
and its condition; the entry dated **2026-09-10** lifts the deferral for Boston, now that
Phase 32 has shipped. Content farms and crawler-written neighborhood pages stay out of scope,
and the map stays reviewed-only.

## Out of scope for the milestone

Courts (reCAPTCHA-gated, and a tenant-facing product must not display docket data
automatically), registry of deeds (only after legal review), SBA and UCC filings, every
texture source (Wayback, OCPF, review sites), and new cities.
