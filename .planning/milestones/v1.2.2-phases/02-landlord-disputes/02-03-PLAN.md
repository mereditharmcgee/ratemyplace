  <action>
1. Update src/pages/api/disputes.ts to add GET handler:

GET /api/disputes (admin only):
- Check context.locals.user exists, return 401 if not
- Check context.locals.user.isAdmin, return 403 if not
- Query disputes with joined review and building data:
  ```sql
  SELECT
    d.*,
    b.address as building_address,
    r.review_text,
    r.review_title,
    r.overall_score as review_overall_score
  FROM disputes d
  JOIN reviews r ON d.review_id = r.id
  JOIN buildings b ON r.building_id = b.id
  ORDER BY d.created_at ASC
  ```
- Return { disputes: results }

2. Create src/pages/api/disputes/[id].ts with PATCH handler:

PATCH /api/disputes/{id} (admin only):
- Auth guard same as GET
- Parse body: { resolutionOutcome, resolutionNotes }
- Validate outcome is one of: 'uphold', 'dismiss', 'partially_valid'
- Validate resolutionNotes is non-empty string (per user decision: notes required)
- Get dispute details for email: landlord_email, landlord_name
- Return 404 if dispute not found
- Update dispute:
  ```sql
  UPDATE disputes
  SET status = 'resolved',
      resolution_outcome = ?,
      resolution_notes = ?,
      resolved_at = unixepoch(),
      resolved_by = ?,
      updated_at = unixepoch()
  WHERE id = ?
  ```
- If outcome is 'uphold', send notification email:
  - Get RESEND_API_KEY from runtime.env
  - Call sendDisputeUpheldEmail(apiKey, landlordEmail, landlordName, resolutionNotes)
  - Log error if fails but don't fail the request
- Return { success: true }
