Required sections (in order):

2. **Summary** (one paragraph) — State the verdict in the first sentence. Cite the three pillars: SameSite=Lax + Cloudflare Turnstile + Astro checkOrigin. State that no token-based CSRF is implemented or required.

3. **Defense Stack** — Bullet list of the controls in play with file/line references:
   - SameSite=Lax session cookie (`src/middleware.ts:29` and `src/middleware.ts:40`)
   - SameSite=Lax OAuth state cookie (`src/pages/api/auth/google.ts:21`)
   - Astro `security.checkOrigin` default (true for SSR; `astro.config.mjs` does not override)
   - Cloudflare Turnstile on public POST forms (signup, forgot-password, contact, disputes, bug-reports)
   - Phase 17 content-type guards on public endpoints (rejects requests with wrong content-type)
   - Phase 17 per-IP rate limits on every public POST + search endpoint
   - OAuth redirect URI allowlist (Google OAuth client config)

4. **Astro checkOrigin — Exact Behavior (CRITICAL)** — A clearly headed callout box explaining what checkOrigin actually does. From RESEARCH.md verified source code:
   - SAFE methods (GET/HEAD/OPTIONS) bypass entirely
   - POST/PATCH/PUT/DELETE with form-like content-type (`application/x-www-form-urlencoded`, `multipart/form-data`, `text/plain`) AND non-same-origin → 403
   - **POST with `application/json` content-type bypasses the origin check entirely** — this is the load-bearing finding
   - POST with no content-type AND non-same-origin → 403
   - Cite source: `node_modules/astro/dist/core/app/middlewares.js` (read directly during research)

5. **Per-Endpoint-Category Coverage** — Four subsections, each with: list of endpoints, primary defense, secondary defense, why-it's-sufficient:

   **5.1 Authenticated POST endpoints** (e.g., `/api/reviews` POST, `/api/admin/*`, `/api/profile/*`, `/api/notifications/*`):
   - Primary: SameSite=Lax session cookie. A cross-origin attacker page cannot read the session cookie value, and Lax means the session cookie is NOT sent on cross-site POST requests (form submissions from attacker.com → ratemyplace.org POST will arrive without the session cookie → request rejected by auth middleware).
   - Secondary: Turnstile is NOT applied to authenticated routes (would degrade UX); not needed because the SameSite=Lax cookie attribute is the controlling factor.
   - Note: Lax (not Strict) is intentional — Strict would break the Google OAuth callback (cross-site top-level redirect drops the cookie). See REQUIREMENTS.md "Out of Scope".

   **5.2 Public (unauthenticated) POST endpoints** — `/api/auth/signup`, `/api/auth/login`, `/api/auth/forgot-password`, `/api/auth/resend-verification`, `/api/contact`, `/api/disputes`, `/api/bug-reports`:
   - Primary defenses vary per endpoint:
     - signup, forgot-password, contact, bug-reports → Turnstile + Phase 17 rate limit + form content-type → covered by Astro checkOrigin (form-like content-type triggers origin check)
     - login → Phase 17 rate limit + password authentication (no Turnstile; cross-origin attacker doesn't gain anything from POSTing to login since they don't have credentials)
     - resend-verification → Phase 17 rate limit + token-in-URL (subsequent verify requires the token sent to the email)
     - **disputes → Turnstile + Phase 17 rate limit + Phase 17 content-type guard. Disputes uses `application/json` content-type, which means Astro checkOrigin DOES NOT apply. The actual CSRF protection for disputes is Turnstile (proves human) + content-type guard (rejects form-encoded requests an attacker could craft) + rate limit. Document this gap explicitly: it's covered, but not by checkOrigin.**

   **5.3 GET endpoints** (search, autocomplete, building detail, etc.):
   - No CSRF concern. CSRF requires a state-changing request; GETs are read-only by convention. CSRF discussion is out-of-band; documented for completeness.
   - Note: GET endpoints have other concerns (rate limiting, query length validation — handled in Phase 17), but CSRF is not one of them.

   **5.4 OAuth callback** (`/api/auth/google/callback`):
   - Primary: SameSite=Lax `state` cookie (set in `/api/auth/google.ts:21`) is sent on the cross-site top-level redirect from Google's domain back to ratemyplace.org. The callback compares the cookie value to the `state` query parameter; mismatch → reject.
   - Secondary: Google OAuth redirect URI allowlist — Google only redirects to URIs registered in the OAuth client config.
   - Note: This is the only place SameSite=Strict would break — Strict drops the cookie on cross-site top-level navigation, including OAuth provider redirects.

6. **Out of Scope (explicit)** — Brief list with one-line justifications, mirroring REQUIREMENTS.md:
   - Token-based CSRF (double-submit cookie) — sufficient defenses already in place; adds bundle weight for no capability gain
   - SameSite=Strict migration — breaks Google OAuth callback (anti-feature)
   - CSP / X-Frame-Options revisit — separate concern, already in middleware.ts
   - Astro 6 / `@astrojs/cloudflare` v13 upgrade — its own milestone

7. **Re-audit Triggers** — Date-only stamp (audited 2026-04-28); no calendar revisit deadline. Re-audit organically when:
   - Astro major version upgrade (Astro 6+) — checkOrigin behavior may change
   - Lucia replacement — session cookie attribute defaults change
   - New OAuth provider added — new state-cookie pattern to validate
   - New non-form content-type endpoint added (like disputes.ts is JSON) — verify checkOrigin coverage gap is closed by Turnstile + rate limit + content-type guard

8. **Sources** — File paths read during research (mirror RESEARCH.md "Sources" section). Include node_modules paths for the Astro middleware source if cited.
