<objective>
Standardize rate-limit response headers across all 9 rate-limited endpoints. Close the SEC-07 gap (`contact.ts` 429 missing `Retry-After`) and add `X-RateLimit-Limit` + `X-RateLimit-Remaining` (SEC-08) to every 200, 429, and 503 response.

Purpose: Rate-limit clients (E2E tests, CLI tools, monitoring systems, automated callers) cannot tell when to retry without `Retry-After`, and cannot self-throttle without `X-RateLimit-*` headers on success responses. Phase 17 SEC-07 was deferred to here as a clean header-only patch.

Output: A new exported helper `buildRateLimitHeaders(result, limit)` in `src/lib/rateLimit.ts`, unit tests covering all three result shapes (allowed, blocked, error), 9 endpoints retrofitted to emit the three headers on every rate-limited response, and an E2E describe block proving the headers land on the wire.

    ```typescript
    /**
     * Build the standard rate-limit response headers.
     *
     * Spread the return value into a Response's headers object. Always emits
     * X-RateLimit-Limit and X-RateLimit-Remaining; emits Retry-After iff the
     * request was blocked (covers both 429-by-rate and 503-fail-closed paths).
     *
     * @param result - the RateLimitResult returned by checkRateLimit
     * @param limit - the maxAttempts argument passed to checkRateLimit (e.g., 3, 5, 60, 120)
     */
    export function buildRateLimitHeaders(
      result: RateLimitResult,
      limit: number
    ): Record<string, string> {
      const headers: Record<string, string> = {
        'X-RateLimit-Limit': String(limit),
        'X-RateLimit-Remaining': String(result.remaining),
      };
      if (!result.allowed) {
        headers['Retry-After'] = String(result.retryAfterSeconds);
      }
      return headers;
    }
    ```
