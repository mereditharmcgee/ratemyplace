# fix/admin-alerts: owner alerts for every intake, and email failures that leave a trace

## Revision notes: how each critique point was resolved

**Important points**

1. **Production check 5.6 (password reset) is removed.** A password reset is not a reliable way to exercise a send to the owner. `forgot-password.ts` L100-104 returns success without sending anything for a Google-only account. The step is replaced by an optional contact-form submission, which exercises two tracked sends (§5 step 6). A new unit test pins the Google-only branch so this mistake cannot recur unnoticed.
2. **TS7053 and raw snake_case on the dashboard.** No `.astro` file indexes a `Record<EmailKind, …>` with a `string`. Two exported helpers handle labels: `emailKindLabel(kind: string)` and `emailReasonLabel(reason: string)`. Both fall back to `humanize()`, and `describeEmailFailure` and the "Last notice" line both use them. New tests cover an unknown kind and walk every known kind.
3. **One overwritable `email_last_failure` key.** It is replaced by one last-failure key per channel:
   - `email_last_failure_owner`: owner notices and the contact notification
   - `email_last_failure_records`: breaker and resumed alerts
   - `email_last_failure_public`: everything sent to members of the public

   A dispute confirmation that bounces can no longer hide an owner-notice or breaker failure. `capped` is no longer counted as a failure: it gets its own counter `owner_notice_capped_count` and its own log event `owner_notice_capped`.
4. **Contract test and per-route tests.** The contract test now compares counts per file: the number of `send…Email(` call sites must be ≤ the number of `trackSend(`/`trackEmail(` calls. A new `emailTrackingRoutes.test.ts`, plus additions to `recordsApprovalEnqueue.test.ts` and `recordsCorrectionAdminRoutes.test.ts`, asserts the exact kind and recipient hash for every tracked send.
5. **A failure result with no `reason`** is recorded as the dedicated reason `'unknown'`, labelled "the send failed, reason not recorded". `'exception'` is not used for this case, because nothing proves an exception happened. This is tested.

**Minor points.** All are adopted:
- Corrected anchors: `migrations/AGENTS.md` L122-132; Worker README L42-47 and L113-116.
- Test schemas are loaded from the migration files (0012, 0018, 0020), not copied.
- U+202F is written out as an escape.
- `npm ci` in the worktree; the worktree has no secrets.
- Wording changed to "existing assertions unchanged".
- Background writes use two sequential `.run()` calls, not `db.batch`, so they can never nest a transaction. Tests flush before they assert.
- The fail-open scope is spelled out in `src/lib/AGENTS.md`.
- Caps are per kind, plus a site-wide daily cap.
- Notice subjects carry an ET time suffix, so Gmail does not thread them together.
- Every failure record carries the request host (`source`), so a preview deploy's failure is labelled as one.
- The building address in a notice is truncated to 200 characters.
- The disputes test uses an `https://ratemyplace.org` request URL.

All missing tests are added and marked **NEW** in §2.

## 1. Design

### 1.1 Recipient
- Export `OWNER_NOTIFY_EMAIL = 'meredith@ratemyplace.org'` from `src/lib/email.ts`.
- Use it in `sendContactNotificationEmail` (no behavior change) and in every new owner notice.
- **No new env var or secret.**
- The Worker keeps `RECORDS_ALERT_EMAIL`. When it is unset or whitespace, alerts fall back to `OWNER_NOTIFY_EMAIL` (owner decision; recommended).

### 1.2 New and changed modules

All new `src/lib` modules use only Worker-safe imports: no `node:` imports and no runtime `astro` import. `runtime.ts` and `db.ts` import `astro` and `@cloudflare/workers-types` as types only.

**1. `src/lib/siteSettings.ts`** (new). A LEAF module: it imports only `type { RecordsDb, RecordsPreparedStatement } from './records/types'`. It holds the site-level `app_settings` keys, kept apart from the records keys.

The SQL for each statement:
- **Write** (same as `records/settings.ts` L59-60): `INSERT INTO app_settings (key, value, updated_at) VALUES (?, ?, ?) ON CONFLICT(key) DO UPDATE SET value = excluded.value, updated_at = excluded.updated_at`.
- **Increment** (atomic; a non-numeric value counts as 0): `INSERT INTO app_settings (key, value, updated_at) VALUES (?, '1', ?) ON CONFLICT(key) DO UPDATE SET value = CAST(CAST(app_settings.value AS INTEGER) + 1 AS TEXT), updated_at = excluded.updated_at`.

**2. `src/lib/format.ts`**: add `export function formatEasternDateTime(unixSeconds: number): string`.
- Use a module-level `Intl.DateTimeFormat('en-US', { timeZone: 'America/New_York', month: 'short', day: 'numeric', year: 'numeric', hour: 'numeric', minute: '2-digit' })`.
- Then apply `.replace(/[  ]/g, ' ') + ' ET'`. Newer ICU puts U+202F before AM/PM. Node 24 here emits plain spaces, but the Workers ICU may not.
- A non-finite input returns `'Time not recorded'`.
- The output is always ASCII, so it is safe in a subject line.

**Behavior:**
- **`trackEmail` never rejects.**
  - It awaits `sending`. A rejection becomes `{ success:false, error:'Failed to send email', reason:'exception', code: err.name }`.
  - On success it returns the result and writes nothing.
  - On failure it builds `{ at: now(), kind, reason: result.reason ?? 'unknown', code: sanitize(result.code), httpStatus: result.httpStatus ?? null, recipientHash: recipientHash(to), source }`, where sanitize keeps `/^[A-Za-z_]{1,64}$/` and otherwise gives null. It calls `recordEmailProblem`, then returns the original result unchanged.
- **`recordEmailProblem` never rejects.**
  1. It logs first, always:
     - For any reason except capped: `logError('email_send_failed', { kind, channel, reason, code, http_status, recipient_hash, source })`.
     - For `capped`: `logError('owner_notice_capped', { kind, recipient_hash, source })`.
     - It never logs the address or Resend's `message`.
  2. Then, in try/catch, it awaits two **sequential `.run()` calls, not `db.batch`**:
     - `writeSiteSettingStatement(<channel key>, JSON.stringify(record), at)`
     - `incrementSiteCounterStatement(reason === 'capped' ? ownerNoticeCappedCount : emailFailureCount, at)`

     No BEGIN is issued, so a background write can never collide with a request's own batch. The two writes are not atomic; this is acceptable for a best-effort trace, and the record is written first.
  3. A catch logs `logError('email_failure_record_failed', { kind, error: err.message })`.
- **`recordOwnerNoticeSent`** writes `owner_notice_last_sent` = `{ at, kind }`. It is best-effort and never rejects.
- **`readEmailHealth`** catches everything.
  - It does one `readSiteSettings` call over all six keys.
  - Malformed JSON or an unknown shape gives null rather than a throw.
  - On a DB error it returns `{ unavailable: true, lastFailure: { owner:null, records:null, public:null }, failureCount: 0, cappedCount: 0, ownerNoticeLastSent: null }`.

**6. `src/lib/ownerNotify.ts`** (new).
- **Imports:** `astro` types, `./runtime` (getEnv, fireAndForget), `./db`, `./rateLimit`, `./logger`, `./email` (OWNER_NOTIFY_EMAIL, sendOwnerNoticeEmail, type OwnerNoticeKind), `./emailHealth`, and `./trackSend` (requestSource).
```ts
export const OWNER_NOTICE_PER_KIND_HOURLY = 6;
export const OWNER_NOTICE_PER_KIND_DAILY = 15;
export const OWNER_NOTICE_SITE_DAILY = 40;
export const OWNER_NOTICE_ADMIN_PATH: Record<OwnerNoticeKind, string> = {
  review_submitted: '/admin/reviews?status=pending', review_edited: '/admin/reviews?status=pending',
  bug_report: '/admin/bug-reports', record_correction: '/admin/records', dispute: '/admin/disputes', verification_upload: '/admin/verify',
};
/** Deliberately only a kind and a building id: a route cannot pass PII into a notice. */
export interface OwnerNotice { kind: OwnerNoticeKind; buildingId: string | null; }
export interface OwnerNoticeDeps { db: SiteSettingsDb; apiKey: string | undefined; siteUrl: string; source: string | null; now?: () => number; }
export async function notifyOwner(deps: OwnerNoticeDeps, notice: OwnerNotice): Promise<void>;
export function queueOwnerNotice(context: APIContext, notice: OwnerNotice): void;
```
**`notifyOwner`** wraps its whole body in try/catch, logging `owner_notice_failed`, so it **never rejects**. It runs these steps:
1. Set `at = now()` and `emailKind = owner_${kind}`.
2. Check three caps in this order:
   - `checkRateLimit(db, kind, 'owner-notice-hour', 6, 3600)` (key `owner-notice-hour:<kind>`)
   - `checkRateLimit(db, kind, 'owner-notice-day', 15, 86400)` (key `owner-notice-day:<kind>`)
   - `checkRateLimit(db, 'site', 'owner-notice-day', 40, 86400)` (key `owner-notice-day:site`)

   The per-kind caps mean a bug-report flood cannot suppress review notices. The site cap protects the Resend quota.
   - **Denied:** if any check returns `!allowed && !error`, call `recordEmailProblem({ at, kind: emailKind, reason: 'capped', code: null, httpStatus: null, recipientHash: recipientHash(OWNER_NOTIFY_EMAIL), source })` and return.
   - **Limiter error:** if a check returns `error: true`, log `owner_notice_cap_unavailable` and **continue (fail-open)**. Scope: every intake except review edit runs its own fail-closed limiter on the same `rate_limits` table first, and it returns 503 before any insert. In practice this path is reached only by review edits, or by a limiter failure in the moments between the intake's own check and the notice's. It is not a general relaxation of the fail-closed rule; `src/lib/AGENTS.md` says so.
3. If `buildingId` is set, run `SELECT address FROM buildings WHERE id = ?`. A failure or missing row gives null and logs `owner_notice_address_lookup_failed`.
4. Set `adminUrl = siteUrl.replace(/\/+$/, '') + OWNER_NOTICE_ADMIN_PATH[kind]`.
5. Set `result = await trackEmail(db, { kind: emailKind, to: OWNER_NOTIFY_EMAIL, source }, sendOwnerNoticeEmail(apiKey ?? '', OWNER_NOTIFY_EMAIL, { kind, buildingAddress, receivedAt: at, adminUrl }), () => at)`.
6. If `result.success`, call `recordOwnerNoticeSent(db, emailKind, at)`.

**`queueOwnerNotice`** runs in try/catch, logging `owner_notice_queue_failed` with `{ kind }`, so it **never throws**:
```ts
const env = getEnv(context);
fireAndForget(context, notifyOwner({ db: getDB(context), apiKey: env.RESEND_API_KEY,
  siteUrl: env.SITE_URL || new URL(context.request.url).origin, source: requestSource(context) }, notice));
```
